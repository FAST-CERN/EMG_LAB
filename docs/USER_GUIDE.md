# EMG Lab 操作教程

用这套软件完成一次肌电实验：**连接设备 → 采集数据 → 训练模型 → 使用模型**。没有硬件也能选择模拟设备，完整体验机器人和灵巧手实验。

点击首页的“操作教程”或实验窗口右上角的“帮助”，或按 **F1**，可随时打开本教程。帮助窗口可以保持打开，边看边操作。左侧选择章节，上方输入关键词搜索；“开发技术文档”页介绍代码和算法。

## 1 首次启动和选择实验

首次使用教师发放的学生离线包：先完整解压，再双击 `install.cmd`，安装完成后双击 `start.cmd`。随包提供 Python、依赖和场景资源，安装及模拟实验无需联网。出现首页后，选择一个实验目标。

首页选择机器人或灵巧手，再选择 **任务方案**。采集、训练和使用模型三页都有同一个方案选择框，在任意一页切换，另外两页同步更新。这里只显示当前实验线的两个方案；切换实验线请用右上角“切换实验”。第一节课先使用基础方案，跑通后再选择扩展方案。

| 课程任务 | 输出类别 | 默认时长（5 组） |
| --- | --- | --- |
| 机器人基础四类 | 停止、左转、右转、前进 | 约 160 秒 |
| 机器人七类 | 停止、左转、右转、前进、后退、左移、右移 | 约 280 秒 |
| 灵巧手基础三类 | 停止保持、张开、握合 | 约 120 秒 |
| 灵巧手五类姿态 | 停止保持、张开、握拳、食指指向、双指伸展 | 约 200 秒 |

时长包含每个动作前 3 秒准备与 5 秒动作。切换任务后，采集标签、模型类别、动作提示和场景指令一起更新。原来的四类、三类文件仍可使用；扩展任务需要重新采集对应类别，不能把旧模型改名当作新模型。

训练和推理页直接展示当前方案的完整类别，列表只显示与方案匹配的数据和模型。“数据与模型”页可跨任务浏览、导入导出；选择用途时自动切换到匹配任务。同一次训练不能混用不同任务。

第一次使用建议选择模拟设备。先熟悉整套流程，再由助教连接实际设备。

界面中蓝色按钮为当前主要操作。组别、名称和常用配置直接展示，运行时仍可查看；评分细节和连接技术参数按需展开。底部操作栏固定，窗口较小时可滚动正文。

开始采集、训练或推理后，页面会滚动到动作提示、训练进度或识别结果。向上滚动即可查看本次配置；配置保持展开，任务结束前暂时不能修改。

## 2 连接设备与观察波形

1. 在“01 设备连接”选择 **模拟设备（无需硬件）**。
2. 保留传感器 `1,2,3,4`，点击“连接设备”。
3. 看到“已连接”和持续变化的波形后，进入“02 采集数据”。

连接实际 Cometa 或 Delsys 时，按助教提供的设备型号、传感器编号和顺序设置。Delsys 使用配对编号，并需要设备驱动、.NET 8 和 SDK 许可。

波形默认显示最近 3 秒、滤波后的信号，纵轴固定为 ±1。波形上方直接提供时间窗口、显示内容和纵轴范围；选择“原始 + 滤波”可对比两种信号。蓝色为滤波后信号，灰色为原始信号。“暂停画面”仅冻结预览，设备仍在收数。

不同设备信号的单位可能不同；若波形看似太小或被截断，先检查纵轴范围和设备状态。实验过程中保持电极位置、传感器顺序和动作含义一致。

波形下方会提示超过 1 秒未收到数据，或某通道连续 2 秒完全不变化。提示异常时先检查设备；“数据正在变化”仅说明有变化，不代表信号质量、佩戴或标签一定正确。

## 3 采集和保存数据

在常显的“采集设置”中，填写组别或学号、数据名称，例如 `G03`、`右手练习_第一次`。

- 默认采集 **5 组动作，每个动作 5 秒**。
- 每个动作前准备 3 秒；准备时放松，动作提示出现后再做约定的肌肉动作。
- 各任务默认时长见上表，场景加载时间不计入采集。
- 可勾选“每组打乱动作顺序”；每组仍完整覆盖所有类别，实际顺序自动写入数据。首次操作保持不勾选即可。
- 数据名称建议写“人员编号_第几轮”。点击“采集记录…”填写操作者代号、佩戴轮次、通道位置和动作映射。均为选填，同组同方案自动复用；换人或重新佩戴后请更新。记录随数据导出，不需要另填表单。
- 一次采集是一个 session，自动保存为一个 `.emg` 文件。每一组完整动作叫一个 trial。

点击“开始采集并保存”，等待场景准备好，再跟随提示完成动作。采集结束自动保存，并在训练页选中本次数据。

采集过程中若做错动作、掉电极或明显受干扰，点击“标记本组无效”并选原因。整组动作仍保留在原始文件中，但训练与基础回放评估会跳过这一组；软件不会自动重采，请结束后按需补采。

“提前结束并保存”会保留已有数据。已经完成的整组动作仍可训练，未完成的一组不用于训练；若连一组都未完成，数据会显示为不可用于训练。

数据自动保存在 `data/<组别>/recordings/`。重复使用同一个数据名称不会覆盖原文件。灵巧手采集时的 3D 手仅演示动作标签。机器人七类的准备阶段显示中文动作与倒计时；动作阶段保留中文名并显示地面箭头或停止符号。侧移使用直箭头，转向使用弯箭头，方向以机器人自身为准。

## 4 训练与理解结果

1. 进入“03 训练模型”，勾选要使用的数据。可点击“选择最近一次采集”快速选择。
2. 输入容易识别的模型名称。
3. “模型设置”中的学习遍数默认 **30 遍**，点击“开始训练”，等待保存完成。
4. 进入“04 使用模型”，刚训练的模型会自动选中。

一份数据、一个完整动作组就可以训练。合并多份数据时，组别、实验目标、设备、传感器编号和顺序、采样率、单位、滤波设置应保持一致。

| 完整动作组数量 | 软件如何评估 |
| --- | --- |
| 1 组 | 全部用于训练，显示“尚未评估推理效果” |
| 2 组 | 一组训练、一组验证，尚未独立测试 |
| 3 组及以上 | 按整组划分训练、验证和测试 |

优先看“测试回放最终指令正确率”和各动作的正确比例。窗口分类正确率只看模型概率最大的类别；最终指令还经过置信度和连续判定，因此两项分数可能不同。

如果某类表现不好，检查该动作的标签、信号和电极，再补采数据。模拟数据的成绩用于演示流程，不能当成真实肌电的准确率。

## 5 实时推理和文件回放

**使用实时信号**

选择模型和“使用设备的实时信号”，确认设备已连接，点击“开始推理”。模拟设备下，可以改变“模拟输入的动作”，观察当前任务各类别的概率、最终指令和 3D 场景。

默认运动指令需要概率至少 65%，连续 3 次一致才开始输出。停止类别或低置信度立即回到停止指令。模型输出不是逐帧跟随你的下拉框，而是对生成的模拟肌电进行解码。

**回放已有数据**

先停止推理并断开采集设备，再选择“回放已采集的数据”，选择记录或进入“数据与模型”导入并点击“用于回放”，然后开始推理。回放按采集时的时间节奏运行。

模型和输入的实验目标、设备类型、传感器编号与顺序、采样率和单位必须匹配。停止后可以重新选择模型或数据。

机器人固定分类默认前进目标速度 0.6 m/s、转向 1.0 rad/s；七类任务的后退与侧移为 0.4 m/s。基础三类灵巧手控制四指联动，停止保持当前位置。

五类灵巧手采用厂商官方仿真示例中的四个目标姿态：张开、握拳、食指指向、双指伸展；另加“停止保持”。切换时先伸开四指、调整拇指、再到目标姿态。新指令接管当前姿态，重复指令不会重启动作，停止立即取消未完成动作并保持。指令文字可能先于手到达姿态，这是平滑运动所需时间。

**选择练习或基础评估**

- **自由练习**：没有固定提示序列；实时肌电驱动场景。机器人可练习“前进—停止—转向—前进”，七类再加入后退与侧移；灵巧手练习到达姿态后停止保持。文件回放也能观察同一段信号的控制效果。
- **基础评估 + 实时信号**：每类出现两次，顺序随机。每次准备 3 秒、动作 3 秒，跟随界面的目标提示完成动作。机器人或手始终由预测指令驱动，提示标签不会代替模型控制。
- **基础评估 + 文件回放**：按照记录原有标签对照预测。与实时推理使用同一场景。使用训练、验证或模型原测试记录时，报告标注为模型关联数据自查；想检查新一轮效果，请另采未参与模型制作的记录。

评估结束自动停止并保存，点击“打开评估报告”查看正确率、混淆矩阵，以及停止段误动作比例、每段首次正确响应、指令切换次数和最长连续正确跨度。这些统计描述解码输出，不是机器人到位时间或真实手指精度。历史报告也可在“数据与模型 → 评估记录”查看或多选导出。HTML 与 JSON 报告位于 `data/<组别>/evaluations/`；提前停止也保存报告并标明未完成。计分只使用动作开始 0.2 秒后完整落在动作段内的推理窗口，准备期不计分；重叠窗口数不是独立动作次数。模拟数据报告只验证软件流程。基础评估不包含金币任务、路径完成率或比赛排名。

## 6 统一管理与导入导出

进入顶部“数据与模型”页，也可从首页、训练页或推理页的管理按钮进入。

1. 按文件类型、实验目标、组别、采集设备筛选。搜索框支持名称、组别和编号。
2. 日期可选择全部、最近 7 天、最近 30 天或自定义起止日期；使用原始采集/训练日期，两端均包含。
3. 点击行并打开“文件详情”，可查看通道、采样率、单位、类别、记录编号与位置；勾选复选框用于批量操作。
4. “勾选筛选结果”只选当前显示的文件；变更筛选后隐藏的文件会自动取消勾选。

**导入文件**

点击“导入…”→“导入数据 / 模型文件…”，可多选 `.emg` 数据和 `.emgmodel` 模型。文件复制到本机原组别目录，拔掉 U 盘后仍可用。相同内容重复导入复用已有条目；批量导入时成功项保留，失败项显示原因。

旧版数据选择 `emg.bin`，同目录需要 `meta.json` 与 `labels.csv`；旧版模型选择 `model.onnx`，同目录需要 `metadata.json`。不要只复制单个 ONNX 文件。

**导出文件**

勾选数据和模型，点击“导出勾选…”，选择 U 盘或指定文件夹。数据导出为 `.emg`；模型导出为单个 `.emgmodel`，包含 ONNX 与元数据。每次使用新文件名，不覆盖原文件。

**直接进入实验**

- 一份或多份数据 → “用于训练”，自动切换实验并勾选记录；同一次训练要求同组与兼容配置。
- 一份数据 → “用于回放”，自动选择离线来源；开始前需要断开采集设备，并选择兼容模型。
- 一个模型 → “使用模型”，自动切换实验并选中模型，再自行确认输入来源。

采集、训练、推理和场景加载期间，管理页可浏览，但导入导出与用途跳转暂时禁用。

## 7 带回家使用的离线实验包

在管理页勾选数据和模型，点击“导出离线实验包…”，选择目标文件夹。软件创建独立目录，除所选文件外，自动附带本机能找到的模型关联训练数据，以及：

- `manifest.json`：文件校验和、记录/模型编号、关联数据、源码指纹与依赖版本；
- `阅读说明.txt`：另一台电脑的导入、训练和回放步骤；
- `课堂与离线开发约定.md`：采集要求、离线开发与课程验收边界。

导出结果会提示缺少多少关联训练记录。缺失训练数据不一定影响推理，但不能完整复现原训练。

此处导出的是自己的数据与模型；教师发放的 **学生离线包** 另含完整源码、Python、固定版本依赖、3D 资源与模拟示例。两者一起保留。换电脑后解压学生包并运行 `install.cmd`，再导入自己的实验包，不复制他人的 `.venv`。

没有已有数据时，可导入学生包内 `examples/模拟示例包`。示例只有模拟信号，用于熟悉导入、训练和回放，不作为实验结论。

另一台电脑启动软件后，点击“导入…”→“导入离线实验包文件夹”，选择含 `manifest.json` 的目录。软件先检查清单与文件校验和，再导入文件。

离线回放重新解码原始肌电，不是播放标签动作。它与实时推理使用同一模拟场景；金币任务使用同一场景和运控，在“练习方式”中选择；模拟/回放仅记练习成绩，正式局需要真实肌电。离线固定信号无法根据场景位置主动调整，不能代替真实肌电的实时闭环考核。

## 8 常见问题和真机准备

| 现象 | 处理方式 |
| --- | --- |
| 列表为空 | 管理页点击“重置筛选”与“刷新”；训练/推理列表还需检查当前实验目标 |
| 数据无法勾选训练 | 需要至少一个完整且未标记无效的动作组；重新采集或选择其他数据 |
| 导入提示缺少文件 | 数据选完整 `.emg`；模型选 `.emgmodel`，或保留 ONNX 旁的元数据 |
| 提示模型与数据不匹配 | 核对设备、通道编号及顺序、采样率、单位、实验目标 |
| 提示文件包过大 | 单份数据解压后上限 512 MiB，模型包内容上限 128 MiB，元数据上限 4 MiB；分批采集或缩小模型 |
| 3D 场景无法打开 | 检查显卡 OpenGL 驱动；可取消 3D 显示后继续采集和文字推理 |
| 训练失败 | 看底部提示和 `local/train_worker.log`；不要反复覆盖原始数据 |
| 只有一组数据没有正确率 | 训练已经完成，但没有独立评估数据；补采更多完整组 |

真实输出由助教带领配置。设备 SDK 和 USB 驱动、Delsys 许可、机器人 DDS 网卡和 Domain、灵巧手供电与适配器都需确认。

在推理页勾选真实机器人或真实灵巧手，点击连接后先待机；使用真实肌电的实时推理才启用动作。模拟设备、采集演示和文件回放不会启用真实动作输出。停止推理请求停止并保留连接；断开或退出释放设备。

新增的机器人七类与手部五类仅开放仿真输出；真实 DDS 和手部 USB 输出仍限于原基础四类/三类。手部新增姿态已验证模型关节范围、插值、指令切换与显示，没有进行真实手的接触、负载或防碰撞验证。

## 金币任务与正式比赛

机器人任务下，在“04 使用模型”的练习方式选择“金币任务”，填写参赛组别、种子、金币数和限时。开始推理后，原始肌电经当前模型解码，机器人依次收集金币；小地图与相对方位提示帮助寻找目标。默认每局 6 枚、120 秒。比赛速度由程序固定，无需学生调整。

正式模式只接受真实设备实时信号，须使用教师指定种子和已冻结程序；模拟、回放和普通练习不计正式成绩。结束后打开最近一局报告，逐步记录保存在 data/<组别>/competitions/。不同模型统一榜单；固定分类使用基础速度，经教师验收的连续/混合控制可使用进阶速度。做算法对照实验时应统一速度和测试数据，不能把较高速度本身当作算法改进。详见“金币任务与比赛规则”帮助页。
